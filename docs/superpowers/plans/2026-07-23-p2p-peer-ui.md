## Context

`P2PFeature` (src/features/p2p/P2PFeature.ts) has a `peerCount` field that is always 0.
The bug: line 32-37 listens via `window.addEventListener('goamp-node:profile-synced', ...)`,
expecting a browser `CustomEvent`. But the event is emitted by Tauri's `app.emit()` in
`node_client.rs` and is only reachable via `@tauri-apps/api/webviewWindow`'s `webview.listen()`.
`WebampUIFeature` (line 103) already does this correctly for updating the tray tooltip.

The modular architecture provides `ModuleContext` with `ctx.events` (IEventBus),
`ctx.ui` (IUIRegistry: registerPanel, registerShortcut, registerMenuItem),
`ctx.transport` (ITransport). Tests use `MockTransport`, real `EventBus`, mock `ui`,
`LocalKVStorage`. See existing `P2PFeature.test.ts` and `HistoryFeature.test.ts` for patterns.

### Design Decision: Single Source of Truth

**Chosen approach:** Make `P2PFeature` the single source of truth for peer count.

1. `P2PFeature.init()` subscribes to `ctx.events.on(EVENTS.PEERS_UPDATED, ...)` to update
   its internal `peerCount`. It does NOT import Tauri webview APIs (keeps it testable).
2. The Tauri-specific `webview.listen('goamp-node:profile-synced', ...)` stays in
   `WebampUIFeature` (line 103), but instead of directly updating the tray, it now also
   does `ctx.events.emit(EVENTS.PEERS_UPDATED, peerCount)` so the event flows through
   the module bus.
3. `WebampUIFeature` keeps its tray tooltip update inline (no churn -- it already works).

**Why not remove WebampUIFeature's listener entirely?** It would require P2PFeature to
import Tauri webview APIs, coupling it to the runtime and breaking the existing test pattern
(tests are Tauri-free). Bridging in WebampUIFeature (which already imports Tauri APIs) and
relaying via `ctx.events` is the minimal-churn path.

### Note: registerPanel is currently a no-op

`GoampCore.ts` line 122 stubs `registerPanel` as `(_id, _render) => {}`. The panel render
function will be fully testable (returns real DOM), but won't appear in the UI until
`IUIRegistry` is wired to the actual Webamp gen-window system. That wiring is out of scope.
